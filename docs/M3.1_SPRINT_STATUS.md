## Architecture Notes

### InsightCard — 3-Level Progressive Disclosure

The card renders in three states controlled by the `expanded` prop:

1. **Collapsed** — icon + one-line summary + confidence pill
2. **Expanded** — adds correlation detail, sample size, timeframe
3. **Detail modal** — opens `CorrelationDisclaimer` for methodology explanation

The component lives under `apps/web/src/lib/components/insights/`. It must
not import from `$lib/api/insights` using the legacy `InsightDto` type; use
`InsightRead` (the current exported type) instead.

### InsightStore — Non-Blocking Pattern

`InsightStore` (`stores/insights.ts`) must not block the Home screen render on
load failure. The store is already on `main` — see `stores/insights.ts`.

The Home screen CTA must not be gated on a non-empty insights response.

### CorrelationDisclaimer — Modal vs. Route

The disclaimer is implemented as a modal/bottom-sheet component with two
entry points:

1. **Inline modal** — triggered by the ⓘ link inside `InsightCard`.
2. **Standalone route** — `/insights/disclaimer/+page.svelte` renders the
   component with `open=true` and navigates to `/insights` on close.

### InsightMatrix — Placement

`InsightMatrix` renders on two surfaces:

- `/insights` page — above `InsightFeed`, visible when `!loading && insights.length > 0`
- Home screen - below `InsightCard` block

The component itself filters `pointbiserial` insights (`confidence >= 0.2`)
and sorts descending by `|effect_size|`. No filtering is needed at the
call-site — pass the raw `insights` array.
